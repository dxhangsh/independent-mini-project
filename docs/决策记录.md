## ADR-005 · 移植修正：_cut_at_member 的「、」边界裁剪真正生效

- **日期**：2026-09-30 ｜ **决策人**：开发者（AI 发现并提议，开发者批准）
- **背景**：移植 `naming._cut_at_member` 时，新测试暴露原实现的边界回退分支不可达（`cut = s[:max_len]` 恒为前缀 → `not s.startswith(cut)` 恒为假），超长多部件名会留下"半个词"的碎片名，与原项目文档承诺相悖。
- **备选方案**：A. 忠实保留原行为（含缺陷）｜ B. 按文档意图修正
- **决策**：选 B——改为按「、」成员累积裁剪，首个成员自身超长时才硬切兜底。
- **理由**：碎片名违反"语义清晰"的命名规格本意；路径长度硬约束由硬切分支保证，不引入新风险；该缺陷正是本项目的质量故事素材。
- **影响**：行为与原 CLI 在该边界场景下不同（更正确）；已记入错误日志 ERR-004，测试覆盖两种裁剪路径。

## ADR-006 · 默认端口从 8000 改为 8765

- **日期**：2026-09-30 ｜ **决策人**：开发者（AI 排查并提议）
- **背景**：M1 人工验证时发现，本机另一个「订阅」项目长期使用 `127.0.0.1:8000`，其 Service Worker 缓存仍绑定在该源上，与 PicNamer 抢占同一端口并造成页面串扰（浏览器把订阅项目的缓存界面递回来）。
- **备选方案**：A. PicNamer 改端口 ｜ B. 改订阅项目的端口 ｜ C. 共用 8000（先到先得）
- **决策**：选 A，PicNamer 默认端口改为 **8765**。
- **理由**：订阅项目是"原住民"，不动它代价最小；8765 是全新"源"，浏览器无历史缓存，从根上消除 Service Worker 串扰；两个项目此后可同时运行。C 方案会持续互相顶掉端口，排除。
- **影响**：run.ps1、README、main.py 说明同步更新；前端全用相对路径，无代码改动；旧 `127.0.0.1:8000` 源上的订阅项目 Service Worker 建议顺手清理一次（对其自身也更健康）。

## ADR-007 · 落盘前重算 I1：以"静默序号是否仍在"为口径

- **日期**：2026-10-01 ｜ **决策人**：开发者（AI 排查用户验证反馈后提议）
- **背景**：ERR-005——复核页人工改开名字后，方案里过期的 `stem_collision` 标记仍拦截落盘。
- **备选方案**：A. 保留旧标记，一律要求勾选放行 ｜ B. 只要 final 互不相同就放行 ｜ C. 重算：同一 stem 上多个不同部件、且全部仍挂自动名（`stem.ext`/`stem-NN.ext`）才拦
- **决策**：选 C。
- **理由**：A 把人工劳动白白作废；B 会漏掉"流水线自动编号 + 未经人工确认"的场景（I1 的本意正是禁止未经确认的静默序号）；C 精确对应"静默序号仍在"这一需要人看的状态——人工改过任何一个名字即视为已确认，同时保留显式放行通道。
- **影响**：`apply_plan` 引擎语义不变（仍读 issues），重算放在 Web 层（编辑状态在 Web 层才知道）；批内同名重复由引擎预检新增的 `dst_duplicate` 物理拦截，不可放行。

## ADR-008 · 批量处理：单活动批次 + JSON 持久化 + 轮询进度

- **日期**：2026-10-01 ｜ **决策人**：开发者（AI 提议方案与取舍）
- **背景**：阶段二要求多目录批量、断点续跑、进度反馈。
- **备选方案**：
  - 进度：A. 轮询 ｜ B. SSE/WebSocket
  - 批量：A. 单活动批次 + out/batch.json 持久化 ｜ B. 批次队列（多批次并存）｜ C. 数据库存储
- **决策**：轮询 + 单活动批次。
- **理由**：MVP 规模下轮询（1s 间隔）开销可忽略、实现与排错都最简单；个人工具同一时刻通常只跑一批，多批次队列与数据库属过度设计。持久化粒度取"目录级状态变更即落盘、图片级进度只留内存"，兼顾断点续跑与 IO 开销。
- **影响**：`GET/POST /api/batch`、`/api/batch/resume`、`/api/batch/cancel`；同目录集合重新提交自动跳过已完成目录；前端批量面板按目录展示状态与"去复核"入口。

## ADR-009 · PWA 与局域网安装：静态壳缓存 + 自签 HTTPS

- **日期**：2026-10-01 ｜ **决策人**：开发者（AI 提议）
- **背景**：PWA 安装要求 HTTPS 安全上下文。本机 `127.0.0.1` 天然是安全上下文（桌面可直接安装），但手机走局域网 IP 的 HTTP 不是。
- **备选方案**：A. 仅桌面 PWA，手机只做网页 ｜ B. 自签名证书 + uvicorn SSL，手机经 `https://<IP>:8765` 安装 ｜ C. Caddy/内网穿透公网 HTTPS
- **决策**：选 B，`run.ps1 -Lan` 一键启用（tools/make_cert.py 生成含局域网 IP SAN 的自签证书，IP 变更自动重生成）。
- **理由**：B 成本最低且离线可用，自签警告是一次性的教学成本；C 引入公网暴露面与第三方依赖，超出课程项目需要。
- **影响**：新增 cryptography 依赖；Service Worker 策略为「静态壳缓存优先、导航网络优先、/api/* 永不缓存」——AI 推理永远需要后端在线，离线仅保证壳可打开，报告中如实说明。

## ADR-010 · 断点续跑与内容新鲜分工：resume 跳过、submit 按签名刷新

- **日期**：2026-10-07 ｜ **决策人**：开发者（本人实测报障 + AI 排查提议）
- **背景**：实测发现"处理路径图片有变动无法即时响应，还是列出老的图片文件"。两层根因：缩略图浏览器缓存 1 小时（同名路径换图不失效）；批量重提交同目录集合时"跳过已完成目录"直接沿用旧方案快照。
- **备选方案**：A. 重提交一律全部重跑 ｜ B. 按目录内容签名（图片名+大小+mtime_ns）比对，变了才重跑 ｜ C. 前端加"强制重新扫描"按钮人工选择
- **决策**：选 B；`resume()` 保持纯续跑语义（done 一律跳过），`submit()` 对 done 目录比对签名、变动即作废旧快照重新处理。
- **理由**：A 会误伤"目录没变只想继续"的场景（重跑浪费且丢失人工确认上下文）；C 把判断负担推给用户；签名比对本地毫秒级且无歧义。缩略图侧配合 ETag（mtime+size）再验证，从缓存层根治。
- **影响**：新增 4 个回归测试（变动重扫/删图重扫/resume 语义不变/ETag 失效）；快照带生成时间在复核页展示，过期快照对用户可见。
