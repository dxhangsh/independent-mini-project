# 项目范围说明（Project Scope）

> 项目名称：AI 商品图片命名助手（PicNamer）
> 课程：TJU Project-Based CST & AI Foundations · 个人独立小项目（占总成绩 5%）
> 版本：v1.0 ｜ 起草日期：2026-09-30 ｜ 状态：待开发者确认
> 提交截止：2026-12-04

---

## 1. 项目动机

1. **真实痛点**：个人商品图片归档库长期使用 `配件或细节-01..NN`、`商品主体-*` 这类无语义命名，无法"据名识图"——前期分析发现部件词写法多达 415 种、近一半只出现过 1 次，且分布不符合实物照片为主的常识。
2. **前期积累**：已在此痛点上完成过一版 CLI 工具（商品图片批量重命名工具），用本地视觉大模型实现了"逐图取词 → 目录级归并 → 规则后处理"的三段式流水线，并沉淀了安全落盘、journal 回滚等工程资产。但 CLI 形态对非技术用户不友好，复核流程依赖手写 HTML 预览页。
3. **产品化机会**：把验证过的 AI 引擎包装成有完整图形界面的产品，让"选文件夹 → AI 起名 → 逐图复核 → 安全落盘/回滚"全程可视化，是自然且有实际使用价值的下一步。
4. **课程目标**：练习课程讲授的 AI 辅助低代码开发全流程方法论，锻炼"人主导、AI 辅助"的正确协作方式。

## 2. 目标用户

| 用户 | 场景 | 核心诉求 |
|---|---|---|
| 主要：有大量商品/物品照片需要归档的人（电商卖家、闲置卖家、收藏整理者，含开发者本人） | 拍摄/收集大量商品图后批量整理归档 | 命名可读可检索，不 manually 逐张改名 |
| 次要：需要批量整理本地照片命名的普通用户 | 相册、扫描件、素材库整理 | 操作简单，误操作可撤销 |

## 3. 核心价值主张

- **图片不出电脑**：默认本地视觉大模型推理（Ollama），隐私安全。
- **命名可读可检索**：产出 `部件名-信息词` 规范名（如 `充电盒-正面.jpg`、`棋盘、棋子-正面.jpg`），多部件同框用「、」连接。
- **误操作可回滚**：预检零写入、逐条改名不覆盖、journal 记录、整批逆序回滚。
- **双形态交付**：网页版 + PWA 可安装 App 版，同一套代码。

## 4. 功能范围

### 4.1 MVP 包含（In Scope）

1. **文件夹处理**：输入本地图片文件夹路径（或选择目录），扫描出待处理图片（jpg/png/webp/heic 等）。
2. **AI 建议名生成**：调用视觉模型逐图生成建议名，目录级归并词表，规则后处理。
3. **可视化复核**：原图缩略图与建议名并排展示；支持单条修改建议名、跳过某张图。
4. **安全落盘**：预检冲突 → 确认后逐条改名（不覆盖）→ journal 记录 → 支持按批次号整批回滚。
5. **进度与状态**：处理进度、当前阶段（识别中/归并中/待复核/已落盘）实时可见。
6. **设置页**：AI 推理来源切换（本地 Ollama / 云端视觉 API，后者用户自备 Key）；命名参数（商品词前缀等）。

### 4.2 明确不做（Out of Scope）

- 云端图片存储、账号体系、多用户
- 图片编辑、去重、标签库管理（列入 v2 候选，不在本期）
- 跨设备云同步
- macOS / Linux 适配（Windows 优先，与实际使用环境一致）
- 视频文件处理

### 4.3 后续迭代候选（v2 Backlog，不计入本期验收）

- 图片去重与相似图聚类
- 自动打标签、按内容搜索图库
- 更多命名模板（品类词优先模式等）

## 5. 非功能需求

| 维度 | 要求 |
|---|---|
| 隐私 | 默认本地推理，图片不离开本机；切云端 API 时需用户显式确认 |
| 安全 | 落盘前预检零写入；逐条改名不覆盖；journal + 整批回滚；异常自动逆序回滚 |
| 可用性 | 非技术用户 5 分钟内完成一次"扫描→命名→复核→落盘"完整流程 |
| 兼容 | Chrome / Edge 桌面端；PWA 可安装到 Android 桌面 |
| 代码质量 | 后端 pytest 覆盖核心安全逻辑（预检、回滚、命名规则） |

## 6. 技术方案概览

```
┌───────────────────────────── 浏览器 / PWA ─────────────────────────────┐
│  原生 HTML/CSS/JS 单页应用（无构建链）                                   │
│  页面：工作台（扫描/复核/落盘）· 回滚 · 设置                              │
└──────────────────────────────┬───────────────────────────────────────┘
                               │ HTTP (JSON)
┌──────────────────────────────┴───────────────────────────────────────┐
│  FastAPI 后端                                                          │
│  ├─ API：扫描 / 建议 / 复核确认 / 落盘 / 回滚 / 状态                     │
│  ├─ 引擎核心（自商品图片命名项目移植）：vlm 客户端、词表归并、命名规则、     │
│  │   预检、journal、回滚                                                │
│  └─ Provider 层：LocalOllamaProvider（默认）｜ CloudVLMProvider（备选）   │
└───────────────────────────────────────────────────────────────────────┘
```

**复用资产清单**（自 `商品图片命名` 项目移植，保留出处注明）：

- 视觉模型调用与提示词（`qwen3-vl`，max-side 1024 预缩放）
- 目录级词表归并 + 规则后处理逻辑
- 命名安全机制：预检零写入、逐条不覆盖、journal.jsonl、逆序回滚
- 不整体照搬 CLI 与批处理脚本，按 API 形态重写入口

## 8. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 模型识别质量不稳定（已知：归并偶发退化、类别召回偏低） | 建议名不可用 | 保留人工复核必经环节；复核页显著标注低置信项 |
| GPU 单进程独占，多请求并发导致质量漂移 | 生成结果劣化 | 后端模型调用全局串行（沿用网关思路） |
| PWA 在非本机网络访问不到本地后端 | App 版演示受限 | 明确"App 形态面向同局域网使用"；演示用本机/同网段环境 |
| 云端 API Key 泄露 | 安全风险 | Key 仅存本地配置文件，界面不回显明文；不写入代码仓库 |
| 工期与课业冲突 | 延期 | MVP 优先原则；每周检查里程碑；12-04 前留一周缓冲 |

## 9. 验收标准总览

1. 在测试图片目录上完成"扫描 → AI 建议 → 复核（修改/跳过）→ 落盘 → 回滚"全流程，零数据丢失。
2. 落盘产出的文件名符合 `部件名-信息词` 规范；冲突场景（重名/成环）被预检拦截且零写入。
3. 网页版在 Chrome/Edge 可用；PWA 可安装并打开基础页面。
4. pytest 全部通过；关键安全逻辑（预检、回滚、命名规则）有用例覆盖。
5. 至少 3 位真实用户体验并留下反馈记录。
6. 交付：可访问的项目材料（链接/访问路径）+ PDF 报告（命名 `[姓名]/[项目名称].pdf`，内容含项目动机、开发过程、核心功能、问题与解决、试用反馈）。
