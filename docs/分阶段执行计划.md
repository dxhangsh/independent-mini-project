# 分阶段执行计划

> 项目：AI 商品图片命名助手（PicNamer）
> 版本：v1.0 ｜ 起草日期：2026-09-30 ｜ 状态：待开发者确认
> 铁律：严格按阶段推进，**禁止一次性完成全部项目**；每阶段走「思考 → 执行 → 测试 → 验证」闭环；AI 自测通过后须经开发者人工验证达标，才可进入下一阶段。

---

## 通用流程（每个阶段都遵守）

1. **思考**：明确本阶段目标与边界，拆解任务，识别风险（记入开发日志）。
2. **执行**：AI 按任务清单逐步实现；开发者深度参与关键环节（核心决策、代码走查）。
3. **测试**：AI 自测（pytest / 手工冒烟 / 自查清单），修复至通过（异常记入错误日志）。
4. **验证**：开发者按「人工验证清单」逐项检查，达标后在本文件勾选，方可进入下一阶段。

---

## 阶段一：MVP 核心闭环（2026-10-01 ~ 2026-10-18）

**目标**：端到端跑通最小可用流程——选目录 → AI 建议 → 复核 → 安全落盘 → 回滚。

### 任务清单

| # | 任务 | 产出 |
|---|---|---|
| 1.1 | 搭建项目骨架：FastAPI 后端 + 原生前端静态目录 + pytest | 可启动的后端、空页面 |
| 1.2 | 移植引擎核心：vlm 客户端、词表归并、命名规则、预检、journal、回滚（保留出处） | `backend/engine/` |
| 1.3 | Provider 层：LocalOllamaProvider（默认），预留 CloudVLMProvider 接口 | 可切换的模型调用层 |
| 1.4 | API：扫描目录、生成建议名（含进度查询）、获取复核数据 | 后端 API + 用例 |
| 1.5 | API：确认落盘（预检→改名→journal）、按批次回滚 | 后端 API + 用例 |
| 1.6 | 前端工作台页：目录输入、图片网格（缩略图+建议名）、单条修改/跳过 | 工作台 UI |
| 1.7 | 前端落盘/回滚操作与结果反馈 | 完整闭环 UI |
| 1.8 | 端到端冒烟：在测试副本目录完整跑一遍 | 冒烟记录 |

### 验收标准（AI 自测 + 人工验证）

- [ ] 在测试图片目录完成全流程，无数据丢失
- [ ] 冲突场景（目标名已占用/互为成环）被预检拦截，目录零写入
- [ ] 回滚后文件名与处理前完全一致
- [ ] pytest 通过；预检/回滚/命名规则有用例覆盖
- [ ] 开发者亲自在真实小目录（≤10 张图）上验证一遍并记录

## 阶段二：功能完善与体验优化（2026-10-19 ~ 2026-11-15）

**目标**：从"能跑"到"好用"——多目录批量、实时进度、设置页、健壮的错误处理、UI 打磨。

### 任务清单

| # | 任务 | 产出 |
|---|---|---|
| 2.1 | 多目录批量：目录列表管理、逐目录推进、断点续跑（跳过已完成） | 批量能力 |
| 2.2 | 进度反馈：后台任务 + 轮询/SSE，实时显示当前图与阶段 | 进度条/状态区 |
| 2.3 | 设置页：本地 Ollama ↔ 云端 API 切换、模型参数、命名参数（商品词前缀等） | 设置页 |
| 2.4 | 错误处理：模型服务不可用、图片解码失败、路径非法等友好提示 | 错误提示体系 |
| 2.5 | UI 打磨：布局、视觉、键盘操作（确认/跳过快捷键） | 体验优化 |
| 2.6 | 回滚页：批次列表 + 一键回滚 + 结果核对 | 回滚 UI |
| 2.7 | 补测试：Provider 切换、错误分支、断点续跑 | 用例扩充 |

### 验收标准

- [x] 多目录批量处理中途中断后可续跑，已完成目录不重复处理（AI 自测：test_batch_resume_after_crash_skips_done / test_batch_resubmit_same_folders_skips_done）
- [x] 进度实时可见；模型服务未启动时有明确指引而非白屏/卡死（AI 自测：启动前预检 503 + 前端指引；test_scan_rejected_when_service_down）
- [x] 云端 API 模式可用（用户自备 Key），切换不需要改代码（AI 自测：test_cloud_provider_classify_request_shape 验证请求契约；真实 Key 由开发者在 M2 人工验证）
- [ ] 非技术用户按界面指引可独立完成一次全流程（找 1 位同学实测——M2 人工验证）
- [x] pytest 全绿（80 例）
